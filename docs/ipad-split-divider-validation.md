# iPad 分栏手柄验证

基线 `bef559f9`，2026-11-19。问题来自 iPad 真机使用反馈。

## 复现与预期

1. 在 iPad 上打开双栏，保留左侧列表、右侧漫画详情。按住中间手柄，缓慢往右拖，中途停住片刻，再快速往左拖并松手。
2. 将手柄拖到任一端，继续向同一方向拖少许，再反向。缩窄 App 窗口，尽量接近 640 逻辑像素，再试一次。

基线在每次移动后用 500 ms 动画更新左栏宽度，可能出现分隔线在手指停稳后继续追赶的情况。当前拖动计算还会以「窗口宽度减去 640」作除数，宽度等于 640 时存在除零路径。

预期是分隔线在拖动中随手指移动，手指停住时也停住，松手时无回弹。手柄保持按下和松开的平滑形态反馈。空间允许时两栏各至少 320 逻辑像素，到达端点后反向即可离开。窗口宽度等于或小于 640 时两栏均分，恢复正常宽度后沿用原比例。

## iPad 真机集中验收

用合并候选构建，记录构建版本或 commit、iPad 机型、iPadOS 版本、窗口模式和方向。使用触屏。首次设置为允许双栏，打开左栏列表和右栏任意漫画详情。把手柄先拖到大致居中，随后按顺序操作。

| 项目 | 操作 | 通过条件 |
| --- | --- | --- |
| 慢拖与中途停住 | 按住手柄缓慢右拖约四分之一栏宽，中途停 1 秒，保持按住，再拖一小段 | 分隔线跟随手指，中途停住时不继续追赶，继续拖时立即移动 |
| 快速反向与松手 | 较快地左右来回两次，最后一次停在中间并松手 | 反向时没有明显延迟，松手时分隔线不滑行、不跳动或回弹 |
| 手柄反馈 | 触摸手柄后不拖动，观察按住和松开。再开始一次拖动观察 | 手柄按下时平滑变宽、变高，松手后平滑复原；手柄形变不推动分隔线 |
| 左右端点 | 分别拖到两端，继续同向多拖一段，然后不松手、反向拖一小段 | 到端点后两栏均可见，反向即离开端点，无卡死和明显回程空段 |
| 窄窗口 | 用系统窗口缩放逐渐缩窄到仍显示双栏的最小尺寸，尝试拖动，随后恢复正常宽度 | 可拖范围按窗口收窄；无余量时分隔线稳定，两栏可用；恢复后能继续拖动。若系统已切成单栏，记下该窗口模式，精确的 640 边界用组件结果判断 |
| 导航与内容 | 让左列表停在一处可识别的条目、右侧停在已打开的详情。拖动后观察，再去左栏点开另一篇详情 | 拖动本身不重置当前导航页面；左右两边仍可正常点击和滚动 |
| 保存比例和旋转 | 调到便于辨认的非居中比例，松手后等至少 3 秒。退出并重新打开 App，在相同窗口复核；旋转后再回到原方向 | 重启后恢复设置的比例，在可显示双栏的方向使用对应窗口宽度，回到原方向后比例正确 |

逐项记通过、失败或系统条件无法覆盖。若仍觉得滞后，优先记录发生在哪个方向、速度和窗口模式，标明是分隔线跟不上，还是手柄形变带来的观感。可以附上同时拍到手指和屏幕的短视频。
